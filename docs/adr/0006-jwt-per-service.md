# ADR 0006: проверка JWT в каждом сервисе, internal-эндпоинты по ключу

**Статус:** принято.

## Контекст

Требование: Gateway выполняет маршрутизацию и проверку на входе, при этом каждый сервис тоже должен проверять JWT самостоятельно (Resource Server). Отдельно нужны внутренние операции Hotel, недоступные клиентам.

## Решение

- JWT HS256, общий секрет из переменной окружения, issuer `https://stayflow.example`, TTL 1 час.
- Gateway проверяет токен и возвращает JSON 401/403 в формате `ErrorDTO`.
- Hotel и Booking тоже настроены как Resource Server и проверяют токен, роли - через `@PreAuthorize`.
- Внутренние эндпоинты Hotel (`confirm-availability`, `release`) не требуют JWT, но требуют `X-Internal-Api-Key`.
- Gateway блокирует эти пути и удаляет присланный клиентом `X-Internal-Api-Key`.

## Последствия

- обход Gateway не даёт доступа к чужим данным без токена;
- внутренние операции нельзя вызвать снаружи даже с валидным JWT;
- секрет нужно синхронизировать между сервисами, при ротации - перезапуск;
- токен нельзя отозвать до истечения TTL, для учебного проекта приемлемо.

## Альтернативы

- Проверка только на Gateway: противоречит требованию и оставляет сервисы открытыми при прямом доступе.
- OAuth2 с внешним провайдером: избыточно, требует отдельного сервера авторизации.
