# ADR 0004: Resilience4j вместо очередей и брокера

**Статус:** принято.

## Контекст

Вызов Hotel может зависнуть или упасть. Требование - тайм-аут, ограниченное число повторов с ростом интервала и компенсация при исчерпании попыток.

## Решение

В Booking Service настроены программные бины Resilience4j:

| Компонент | Настройка |
|---|---|
| Retry | 3 попытки, экспоненциальная задержка 200 мс, множитель 2 |
| TimeLimiter | 4 с, отмена зависшей задачи |
| CircuitBreaker | окно 10 вызовов, порог 50%, пауза 10 с, 3 вызова в half-open |
| Исполнение | виртуальные потоки Java 21 |

Повторяются только `RemoteServiceException` (сеть, 5xx). Занятость номера (409) и клиентские ошибки не повторяются, иначе бессмысленно.

## Последствия

- отказ Hotel не блокирует поток и не копит запросы;
- ошибки отображаются в 502/503/504;
- параметры заданы в коде `HotelClientConfig`, при необходимости выносятся в конфиг;
- при открытом circuit breaker компенсация выполняется сразу, без ожидания.

## Альтернативы

- Асинхронная обработка через брокер: надёжнее при массовых сбоях, но добавляет отдельный компонент и усложняет отладку.
- Ручные счётчики ошибок: дублируют готовую библиотеку и хуже тестируются.
