# ADR 0001: отдельная база у каждого сервиса

**Статус:** принято.

## Контекст

В требованиях к проекту указаны две независимые схемы: users/bookings в Booking Service и hotels/rooms в Hotel Service. Нужно решить, будет ли общая база или у каждого сервиса своя.

## Решение

Каждый сервис владеет своей in-memory H2: `bookingdb` и `hoteldb`. Общих таблиц нет. Booking хранит только `room_id` и `hotel_id`, данные о номере получает по API.

## Последствия

- сервисы можно менять и разворачивать независимо;
- нет распределённых транзакций, согласованность обеспечивается сагой;
- нужна идемпотентность и компенсация;
- целостность ссылок между сервисами проверяется в момент вызова, а не внешним ключом.

## Альтернативы

- Общая схема с внешними ключами: проще для целостности, но ломает автономность сервисов и противоречит требованию database per service.
- Одна СУБД с разными схемами: ближе к production, но избыточно для учебного проекта на H2.
